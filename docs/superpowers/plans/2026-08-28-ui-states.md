# UI States (Loading / Error / Empty) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add loading skeletons, error boundaries, and empty states to every user-facing route so the app behaves like a production job board (ITviec / Glints quality).

**Architecture:** Shared primitives first (Skeleton, EmptyState, InlineError + 5 shape-matched skeleton variants), then route groups (Jobs → Core user → CV+Messaging → Companies+Recruiter), then global 404. Each task is self-contained; all files in a task are created/modified together.

**Tech Stack:** Next.js 16, React 19, Tailwind CSS, shadcn/ui (existing Card, Button), lucide-react (already installed), Prisma 6, TypeScript strict.

## Global Constraints

- Prisma pinned at v6 — never touch `package.json` to upgrade it.
- DB commands need `NODE_OPTIONS=--dns-result-order=ipv4first` — already in existing npm scripts.
- Next.js 16 file conventions: `loading.tsx` (Suspense boundary, server component OK), `error.tsx` (`"use client"` required, props `{ error: Error & { digest?: string }; reset: () => void }`), `not-found.tsx` (server component, shown when page calls `notFound()`).
- `error.tsx` must call `reset()` on retry — never redirect. `reset()` re-attempts the server render.
- User-supplied values (search term, filter) always go through parameterised queries — no string interpolation in SQL (already enforced; don't break it).
- No unit tests for UI components (zero tests in this entire plan — correct per repo style).
- Each task ends with: `npx tsc --noEmit` (0 errors) + `npm run build` (success).
- Do not add comments unless the WHY is non-obvious.
- `Navbar` import path: `@/components/Navbar` (default export).
- `cn` utility import path: `@/lib/utils`.
- `buttonVariants` import: `@/components/ui/button`.

  icon,
  title,
  description,
  action,

  title: string;
  description?: string;
  action?: ReactNode;

import Link from "next/link";
import { AlertTriangle } from "lucide-react";

export function InlineError({
  message = "Đã có lỗi xảy ra.",
  onRetry,
  backHref,
}: {
  message?: string;
  onRetry?: () => void;
  backHref?: string;
}) {
  return (
    <div className="flex flex-col items-center justify-center py-16 text-center">
      <AlertTriangle className="mb-3 h-8 w-8 text-destructive" />
      <p className="text-sm text-foreground">{message}</p>
      <div className="mt-4 flex gap-3">
        {onRetry && (
          <Button variant="outline" size="sm" onClick={onRetry}>
            Thử lại
          </Button>
        )}
        {backHref && (
          <Link href={backHref} className="text-sm text-primary hover:underline">
            ← Quay lại
          </Link>
        )}
      </div>
    </div>
  );
}

Place this block AFTER all `useState` and `useRef` hooks but BEFORE the `return` JSX — React hooks must always be called in the same order, so the guard cannot go before the hooks.
